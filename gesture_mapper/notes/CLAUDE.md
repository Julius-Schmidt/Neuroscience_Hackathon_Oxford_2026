# Preferences

- Direct, concise communication. No preamble, no restating the question back.
- Minimal formatting unless structure genuinely helps.
- Push back on overstatements; flag when something is uncertain rather than smoothing over it.
- Prefer terse responses on heavy/iterative coding workflows — full explanation only when asked
  or when a decision has real tradeoffs worth surfacing.

## Verification discipline

- Before marking work done, actually run/test it — don't infer correctness from reading code back.
- Prefer Grep over Read when searching for something specific. Read full files only when
  editing them or when grep has already confirmed it's the relevant file.
- For "where does X happen" across multiple files, use a subagent (Task tool) rather than
  reading files directly in the main session.
